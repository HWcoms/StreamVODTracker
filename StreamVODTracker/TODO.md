- [ ]  기존 JSON의 `LocalFilePath`는 `DesktopLocalFilePath`로 옮기는 호환 처리를 마련하고, 기존 Android 참조가 없을 때는 비워 둔다.

- [X]  계정 연결/변경은 OAuth 연결과 로컬 자격 증명 저장만 수행하며 동기화는 별도 버튼으로 시작한다. 연결 해제는 이 PC의 자격 증명만 삭제하고 Drive 파일은 유지한다.
- [X]  데스크톱 OAuth Client ID와 선택 Client Secret 입력, 연결 이메일 표시, 동기화 진행·완료·실패 알림을 제공한다. refresh token은 Windows Credential Manager에 저장한다.
- [X]  Drive API 요청량을 줄이기 위해 저장된 파일 ID로 메타데이터만 확인한다. 전체 JSON은 앱 시작·수동 동기화·원격 `modifiedTime` 변경 때 내려받고, 로컬 변경은 debounce 후 업로드한다.
- [X]  앱이 활성 상태일 때 Drive 동기화 JSON의 `modifiedTime`을 1~2분 간격으로 확인하고, 변경이 감지된 경우에만 JSON을 내려받아 로컬 데이터와 병합한다. 오프라인·앱 비활성 상태에서는 확인을 건너뛰고 다음 실행 또는 재활성화 때 확인한다.
- [X]  자동 확인 간격은 설정 화면에서 시·분·초 입력란으로 조정하며, 기본값은 90초다.
- [X]  주기 확인에는 저장된 파일 ID로 Drive API 메타데이터 조회를 사용하고, API 요청 한도를 고려해 간격을 조정할 수 있게 한다.
- [ ]  Android 백그라운드 실행 제약을 고려하고 실시간 동기화를 보장한다고 가정하지 않는다.
- [ ]  Android 호스트 프로젝트와 플랫폼별 OAuth 클라이언트를 추가한다. 현재 구현은 Windows 데스크톱 OAuth와 Windows Credential Manager만 지원한다.
- [ ]  개발자가 Google Cloud 프로젝트와 Drive API를 준비한다. 앱에는 서비스 계정 개인 키를 포함하지 않고, Android용 Client Secret도 포함하지 않는다.
- [ ]  일반 사용자가 별도 Cloud 프로젝트를 만들도록 요구하지 않는 구조를 검토한다. 배포 시 OAuth 동의 화면·테스트 사용자·검증 요건과 `drive.file` 최소 권한 범위의 실제 파일 접근 흐름을 확인한다.

## 동기화 충돌 방지

- [X]  로컬 CSV 자체를 Drive에서 공유하지 않는다. 각 기기의 로컬 데이터를 Drive JSON과 병합한 뒤 CSV에 저장하고 병합 결과를 JSON으로 업로드한다.
- [ ]  VOD 키는 `Platform + VodId`로 하고, 변경 이벤트에 고유 `ChangeId`, 기기 ID, 레코드 키, 변경 필드와 값, 수정 시각 등을 기록하는 방안을 검토한다.
- [ ]  기기별 이벤트/변경 로그(예: `changes/windows/{changeId}.json`, `changes/android/{changeId}.json`)를 저장하고 다른 기기의 이벤트를 가져와 로컬 데이터에 적용하는 구성을 고려한다.
- [ ]  서로 다른 필드 변경은 병합한다. 같은 필드가 양쪽에서 바뀌면 충돌 정책을 적용하고, 단순 `UpdatedAt` 비교의 한계를 고려해 필요하면 사용자에게 해결을 요청한다.
- [ ]  공유 상태 파일 하나를 두 기기가 동시에 갱신하지 않도록 기기별 동기화 상태를 둔다. CSV는 병합된 현재 상태를 내보내는 결과물로 취급할 수 있다.
- [ ]  구현 복잡도가 과도하면 먼저 충돌을 감지해 사용자에게 알리는 최소 기능부터 구현한다.
- [ ]  SQLite DB 파일 자체를 Drive에서 여러 기기가 직접 열어 동기화하지 않는다. 변경 이벤트 또는 별도 동기화 계층을 사용한다.
- [ ]  삭제 tombstone을 구현한다. 현재 오프라인 삭제는 다른 기기 데이터와 병합될 때 되살아날 수 있고, 두 기기의 동시 수정 충돌은 별도 해결하지 않는다.

## VOD 재생

- [X]  온라인 VOD는 해당 플랫폼 URL을 브라우저 또는 플랫폼 앱으로 연다.
- [X]  Windows에서 `LocalFilePath`가 있으면 지정한 PC 플레이어(예: VLC)를 실행할 수 있도록 한다.
- [X]  설정 팝업에서 MP4 기본 연결 앱 및 Windows에 MP4 실행 앱으로 등록된 플레이어를 드롭다운에서 선택한다. `직접 추가`는 Windows 파일 선택 창에서 EXE를 고른다.
- [X]  플레이어 실행 인수는 플레이어별로 저장하고 프리셋 또는 직접 입력을 지원한다. `{file}`, `{position}`, `{position_hms}` 토큰을 제공한다.
- [X]  카드의 파일 링크를 누르면 설정된 플레이어와 인수로 파일을 연다. 미설정 시 기본 연결 앱을 사용하고 파일/플레이어 경로가 없거나 실행 실패 시 알림을 표시한다.
- [X]  `시청중` 카드의 `LastPositionSeconds`를 재생 시작 위치 토큰에 전달한다. 다른 시청 상태에서는 재생 위치를 0으로 전달한다.
- [ ]  Android에서 PC 전원 상태와 무관하게 Drive의 카드 정보를 조회·수정할 수 있게 한다. 로컬 파일 재생은 해당 파일에 접근 가능한 기기에서만 지원하며, PC 원격 재생 요청이나 PC 상주 서비스는 별도 요구가 있을 때만 검토한다.

## 검증 체크리스트

- [ ]  현재 프로젝트 구조와 기존 구현을 먼저 확인하고 중복 재작성을 피한다.
- [ ]  플랫폼별 디렉터리, 채널 정보 행 및 채널 ID 기반 VOD CSV 읽기·쓰기를 확인한다.
- [ ]  채널 선택 시 해당 CSV만 읽고 캐시 및 캐시 무효화가 동작하는지 확인한다.
- [ ]  신규 VOD 병합, 기존 사용자 정보 보존, 온라인에서 삭제된 VOD 보존을 확인한다.
- [ ]  변경된 채널 CSV만 저장하고 UTF-8, 이스케이프, 잘못된 행 및 저장 안전성을 확인한다.
- [ ]  CSV 가져오기·내보내기 병합을 확인한다.
- [ ]  Windows와 Android의 데이터 필드 및 시청 상태 값이 일치하는지 확인한다.
- [ ]  Windows Pro·Enterprise·Education에서는 Windows Sandbox에 앱을 복사해 새 환경에서 Google 계정 연결, Drive 데이터 가져오기, 변경 업로드를 확인한다. Sandbox를 닫으면 내부 설정과 데이터가 삭제된다는 점을 고려한다.
- [ ]  채널별 로딩, 캐시, 새로고침, VOD 보존, CSV 가져오기·내보내기 검증을 작성한다.

## 구현 우선순위

- [ ]  **1단계:** 프로젝트·데이터 구조 확인, 플랫폼별·채널별 CSV, 채널 로딩, 캐시, 신규 VOD 병합
- [X]  **2단계:** 시청 상태·메모·재생 위치 저장 및 CSV 가져오기·내보내기
- [ ]  **3단계:** 현재 문서의 UI 작업(날짜 입력, URL/파일 경로, 보기 상태, 정렬, 새로고침 알림, 플랫폼 필터)을 기존 구조에 맞춰 반영
- [X]  **4단계:** Windows 데스크톱 Google Drive 계정별 메타데이터 동기화
- [ ]  **5단계:** Android 대상 추가, 기기 간 변경 이벤트와 충돌·삭제 병합

## 카드 툴팁 및 수정 팝업 개선

- [X]  카드 수정과 다시보기 추가 팝업이 동일한 크기, 필드 배치, 파일 선택·날짜 선택 컨트롤 및 버튼 스타일을 사용한다.
- [X]  기존 카드 수정 팝업의 날짜 입력란에 달력 버튼을 추가하고, 선택한 날짜를 입력란에 반영한다.
- [X]  카드 수정 버튼은 한 개 선택일 때 활성화하고, 여러 개 선택일 때 회색 비활성 상태로 둔다. 선택이 없으면 버튼을 숨긴다.

검증: 추가와 수정 창을 같은 500×440 크기와 입력 필드 순서로 맞췄다. 수정 창에도 추가 창과 같은 날짜 달력 선택을 제공하며, 두 창 모두 강조 저장/추가 버튼과 동일한 파일 찾기 버튼을 사용한다.
