# 다음 작업 목록

다음 UI/데이터 작업과 기반 구조 작업은 아래 순서와 우선순위로 진행한다. 완료한 항목은 상태와 검증 결과를 이 문서에서 갱신한다. 구현 전 현재 프로젝트와 데이터 구조를 확인하고, 기존 구현에 적용되지 않은 항목만 추가·수정한다.

## 1. 날짜 입력 달력 — 완료

- [x] 다시보기 직접 추가 팝업의 방송 날짜 입력란 오른쪽에 달력 아이콘 버튼을 둔다.
- [x] 버튼을 누르면 날짜 선택 달력이 열리고, 선택한 날짜가 입력란에 반영된다.
- [x] 직접 입력도 계속 허용하고 기존 날짜 검증을 유지한다.

## 2. URL과 파일 경로 동시 보관 — 완료

- [x] 영상 등록 팝업에서 URL 링크 입력 아래에 파일 링크/경로 입력을 표시한다.
- [x] URL과 파일 경로는 한 영상 항목에 함께 저장될 수 있다.
- [x] 파일이 지정되지 않았으면 파일 링크 행은 빈 상태로 둔다.
- [x] 데이터 모델과 CSV 헤더를 함께 갱신하며 기존 CSV 데이터가 보존되도록 호환 처리를 추가한다.
- [x] 카드에서 URL은 기본 브라우저로, 파일 경로는 연결된 앱으로 연다.
- [x] 기존 카드 수정에서 URL·파일 경로를 각각 입력/선택하고 제목과 방송 날짜를 변경할 수 있다.

## 3. 보기 아이콘의 활성 상태 표시

- [ ] 썸네일 표시/숨김 버튼은 현재 상태가 아이콘으로 구분되어야 한다.
- [ ] 그리드/리스트 보기는 한쪽을 활성화하면 반대쪽을 비활성 상태로 표시한다.
- [ ] 비활성 아이콘 버튼의 배경은 투명하게 하고, 아이콘 정렬과 크기는 현재 버튼 크기에 맞춘다.

## 4. 검색 결과 정렬 — 완료

- [x] 검색창 오른쪽에 정렬 옵션을 배치하고 실제 정렬 기능을 연결한다.
- [x] 방송일순, 최근 추가순, 제목순 기준을 제공하고 방송일순을 기본값으로 둔다.
- [x] 정렬은 검색/선택 채널 결과에 적용하며 CSV 저장 순서나 기존 영상 데이터를 바꾸지 않는다.
- [x] 정렬 선택을 `settings/settings.ini`에 저장해 다음 실행에도 유지한다.
- [x] 정렬 드롭다운 오른쪽 화살표로 오름차순/내림차순을 바꾸고 방향도 설정에 저장한다.
- [x] 시청 상태 필터를 `미시청`, `시청중`, `시청완료`로 표시하고 기본은 모든 시청 상태로 둔다.
- [x] 검색 범위를 영상 제목과 게시 날짜로 제한하고 입력 안내를 `영상 제목 혹은 날짜 검색`으로 표시한다.

구현: 기본 정렬은 방송일 내림차순이며 날짜가 없는 영상은 뒤에 표시한다. 정렬 옵션과 방향은 `[Library] SortOrder`, `SortDescending`에 기록한다.

## 5. 새로고침 결과 알림

- [ ] 새로고침 아이콘을 눌러 채널 영상 조회와 반영이 성공하면 `새로고침 완료` 알림을 표시한다.
- [ ] 조회 결과가 기존 목록과 같아 새로 반영할 내용이 없으면 `새로고침 할 내용 없음` 알림을 표시한다.
- [ ] 조회에 실패하면 성공 알림 대신 실패 알림을 표시하고 기존 목록을 유지한다.

## 6. 스트리밍 사이트별 채널 필터

- [ ] 왼쪽에서 치지직 또는 SOOP을 선택하면 채널 목록에 해당 사이트의 채널 카드만 표시한다.
- [ ] 전체 보관함 등 다른 항목을 선택했을 때의 채널 목록 동작은 기존 탐색 구조에 맞춰 유지한다.
- [ ] 사이트 선택을 바꿀 때 선택된 채널과 다시보기 목록도 일치하도록 갱신한다.

## 7. 플랫폼·채널별 CSV 저장소 — 완료

- [x] 플랫폼별 디렉터리(`chzzk`, `soop`) 아래에 채널 ID 기반 CSV를 저장한다. 채널 목록용 `channels.csv`는 만들지 않는다.
- [x] 파일명은 채널명이 아닌 플랫폼의 고유 채널 ID를 사용한다. 채널 메타데이터는 채널 CSV의 첫 데이터 행에 한 번만 저장하고 VOD 행에는 `Platform`, `ChannelId`를 중복 저장하지 않는다.
- [x] VOD 식별 키는 `Platform + VodId`로 한다. 내보내기/가져오기 파일에는 병합을 위해 두 식별 필드를 포함한다.
- [x] VOD 데이터 필드는 `VodId`, `Title`, `Url`, `PublishedAt`, `WatchStatus`, `LastPositionSeconds`, `LocalFilePath`, `Memo`, `UpdatedAt`를 기준으로 검토한다. 필요한 `DurationSeconds`, `ThumbnailUrl`, `ChannelId`, `Platform`의 포함 여부는 내보내기·가져오기 식별성도 고려한다.
- [x] UI에서 CSV를 직접 다루지 않도록 `IVodRepository` 등 저장소 인터페이스를 두고, 현재 CSV 구현을 추후 SQLite 구현으로 교체할 수 있게 한다.

- [x] 구현: `db/chzzk/{channelId}.csv`, `db/soop/{channelId}.csv`를 사용하고 기존 루트 CSV를 첫 저장 때 새 구조로 이전한다. 채널 정보는 각 CSV에 한 번만 보관하며 저장용 `SourceType`은 `URL` 또는 `파일`로 통일한다. CSV 저장소는 `IVodRepository`를 구현한다.

## 8. 채널 로딩·캐시·저장

- [ ] 치지직 또는 SOOP을 선택한 뒤 채널을 선택하면 해당 채널의 CSV만 읽는다. 다른 채널 파일은 불필요하게 읽지 않는다.
- [ ] 이미 읽은 채널 데이터는 메모리에 캐시하고, 재방문 때 파일을 매번 다시 읽지 않는다.
- [ ] 파일 변경 시각 또는 동기화 버전으로 캐시 유효성을 판단한다.
- [ ] 변경된 채널의 CSV만 저장하고 다른 채널 파일은 다시 쓰지 않는다.
- [ ] CSV는 Windows와 Android에서 한글이 보존되도록 UTF-8을 기본으로 한다. 필드 이스케이프와 잘못된 행 처리를 고려하고, 임시 파일 기록 후 교체하는 원자적 저장 및 백업 방식을 검토한다.
- [ ] 앱 종료 또는 적절한 저장 시점에 변경 데이터만 저장한다.

## 9. VOD 새로고침·병합·보존

- [ ] 새로고침은 선택한 채널을 대상으로 하고 `VodId` 기준으로 비교해 신규 VOD만 추가한다.
- [ ] 기존 VOD의 시청 상태, 메모, 마지막 재생 위치, 로컬 파일 경로를 덮어쓰지 않는다.
- [ ] 온라인 플랫폼에서 삭제되거나 비공개 처리된 VOD도 로컬 레코드에서 자동 삭제하지 않는다.
- [ ] 기존 CSV 데이터 및 사용자 데이터와 호환되도록 병합 규칙을 명시한다.

## 10. CSV 가져오기·내보내기 및 Excel — 완료

- [x] CSV는 앱 데이터의 가져오기·내보내기와 디버깅에 사용한다.
- [x] 가져올 때 플랫폼 및 채널 식별자를 검증하고 VOD ID 기준으로 병합한다. 기존 사용자 시청 정보를 실수로 초기화하지 않도록 한다.
- [x] XLSX는 보고·열람용 내보내기 형식으로 두고, 플랫폼별 데이터를 통합해 `치지직`, `soop` 시트를 정확히 생성한다.

- [x] 구현: 화면에서 CSV 가져오기/내보내기와 Excel 내보내기를 제공한다. 가져오기는 플랫폼·채널 식별자를 확인하고 VOD ID로 병합하며 기존 시청 상태와 마지막 재생 위치를 유지한다.

## 11. Google Drive 동기화 설계

- [ ] Windows와 Android가 같은 데이터를 공유하고, PC가 꺼져 있어도 Android에서 클라우드 데이터를 조회·수정할 수 있는 구성을 검토한다. 별도 유료 서버를 운영하지 않는 방향을 우선 고려한다.
- [ ] Drive API의 무료 저장 공간은 계정 한도 내이며 API에는 프로젝트·사용자별 요청 한도가 있음을 고려한다. 탭 이동 때마다 API를 호출하지 않고 앱 시작, 명시적 새로고침, 데이터 변경 후, 앱 재활성화 등 필요한 시점에 동기화한다.
- [ ] Android 백그라운드 실행 제약을 고려하고 실시간 동기화를 보장한다고 가정하지 않는다.
- [ ] 개발자가 Google Cloud 프로젝트, Drive API, OAuth 설정을 준비한다. Windows와 Android에 맞는 OAuth 클라이언트를 사용하고, 서비스 계정 개인 키나 비밀 자격 증명을 앱에 포함하지 않는다.
- [ ] 일반 사용자가 별도 Cloud 프로젝트를 만들도록 요구하지 않는 구조를 검토한다. 배포 시 OAuth 동의 화면·테스트 사용자·검증 요건과 `drive.file` 최소 권한 범위의 실제 파일 접근 흐름을 확인한다.

## 12. 동기화 충돌 방지

- [ ] 두 기기가 같은 CSV를 직접 수정하고 전체 파일을 올리는 방식만으로는 안전한 동기화를 보장할 수 없으므로 최종 동기화 방식으로 사용하지 않는다.
- [ ] VOD 키는 `Platform + VodId`로 하고, 변경 이벤트에 고유 `ChangeId`, 기기 ID, 레코드 키, 변경 필드와 값, 수정 시각 등을 기록하는 방안을 검토한다.
- [ ] 기기별 이벤트/변경 로그(예: `changes/windows/{changeId}.json`, `changes/android/{changeId}.json`)를 저장하고 다른 기기의 이벤트를 가져와 로컬 데이터에 적용하는 구성을 고려한다.
- [ ] 서로 다른 필드 변경은 병합한다. 같은 필드가 양쪽에서 바뀌면 충돌 정책을 적용하고, 단순 `UpdatedAt` 비교의 한계를 고려해 필요하면 사용자에게 해결을 요청한다.
- [ ] 공유 상태 파일 하나를 두 기기가 동시에 갱신하지 않도록 기기별 동기화 상태를 둔다. CSV는 병합된 현재 상태를 내보내는 결과물로 취급할 수 있다.
- [ ] 구현 복잡도가 과도하면 먼저 충돌을 감지해 사용자에게 알리는 최소 기능부터 구현한다.
- [ ] SQLite DB 파일 자체를 Drive에서 여러 기기가 직접 열어 동기화하지 않는다. 변경 이벤트 또는 별도 동기화 계층을 사용한다.

## 13. VOD 재생

- [ ] 온라인 VOD는 해당 플랫폼 URL을 브라우저 또는 플랫폼 앱으로 연다.
- [ ] Windows에서 `LocalFilePath`가 있으면 지정한 PC 플레이어(예: VLC)를 실행할 수 있도록 한다.
- [ ] 로컬 영상은 `LastPositionSeconds`부터 재생하는 방안을 검토한다. 외부 플레이어 경로와 인자는 사용자 설정으로 관리하는 방안을 고려한다.
- [ ] Android에서 PC 로컬 영상 재생을 요청하는 기능은 PC가 온라인이고 실행 서비스가 동작할 때만 제공한다. PC가 꺼져 있어도 클라우드 데이터 조회·수정은 가능해야 한다.

## 14. 검증 체크리스트

- [ ] 현재 프로젝트 구조와 기존 구현을 먼저 확인하고 중복 재작성을 피한다.
- [ ] 플랫폼별 디렉터리, 채널 정보 행 및 채널 ID 기반 VOD CSV 읽기·쓰기를 확인한다.
- [ ] 채널 선택 시 해당 CSV만 읽고 캐시 및 캐시 무효화가 동작하는지 확인한다.
- [ ] 신규 VOD 병합, 기존 사용자 정보 보존, 온라인에서 삭제된 VOD 보존을 확인한다.
- [ ] 변경된 채널 CSV만 저장하고 UTF-8, 이스케이프, 잘못된 행 및 저장 안전성을 확인한다.
- [ ] CSV 가져오기·내보내기 병합과 XLSX 시트 이름을 확인한다.
- [ ] Windows와 Android의 데이터 필드 및 시청 상태 값이 일치하는지 확인한다.
- [ ] 채널별 로딩, 캐시, 새로고침, VOD 보존, CSV 가져오기·내보내기 검증을 작성한다.

## 15. 구현 우선순위

- [ ] **1단계:** 프로젝트·데이터 구조 확인, 플랫폼별·채널별 CSV, 채널 로딩, 캐시, 신규 VOD 병합
- [x] **2단계:** 시청 상태·메모·재생 위치 저장, CSV 가져오기·내보내기, XLSX 내보내기
- [ ] **3단계:** 현재 문서의 UI 작업(날짜 입력, URL/파일 경로, 보기 상태, 정렬, 새로고침 알림, 플랫폼 필터)을 기존 구조에 맞춰 반영
- [ ] **4단계:** Google OAuth 및 Drive 파일 접근
- [ ] **5단계:** 기기별 변경 이벤트와 충돌 감지·병합
- [ ] **6단계:** 실제 데이터 규모와 성능 측정 후 SQLite 전환 필요성 판단

> 구현 시 현재 코드와 데이터 구조를 확인하고, 적용되지 않은 요구사항만 추가·수정한다. 설계가 확정되지 않은 부분은 임의로 복잡한 구조를 만들지 말고 선택지를 설명해 확인한다.

## 17. 카드 툴팁 및 수정 팝업 개선

- [ ] 카드에서 잘려 보이는 텍스트 위에 포인터를 올리면 전체 내용을 빠르게 확인할 수 있도록 툴팁을 표시한다.
- [ ] 기존 카드 수정 팝업의 날짜 입력란에 달력 버튼을 추가하고, 선택한 날짜를 입력란에 반영한다.
- [ ] 카드 수정 버튼을 삭제 버튼과 같은 기본/비활성 색상 규칙으로 표시한다. 수정 가능한 카드가 한 개 선택된 경우 활성화하고, 선택이 없거나 여러 개 선택된 경우 회색 비활성 상태로 두어 실행할 수 없게 한다.

## 18. Excel 내보내기 플랫폼별 시트 검증

- [ ] CSV 내보내기에는 치지직과 SOOP 양쪽 VOD가 모두 포함되지만, Excel 내보내기에서는 SOOP 시트에서만 SOOP VOD가 확인되는 현상을 점검한다.
- [ ] Excel 내보내기 결과를 대조해 치지직 VOD와 SOOP VOD가 각각 `치지직`, `soop` 시트에 정상적으로 포함되는지 확인한다.
